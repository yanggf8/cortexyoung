---
name: ast-grep
description: Route code lookup, reusable reads, structural search, and impact questions to rg, ast-grep, or cort
---

Route by the narrowest output that answers the question. Two measurements set the order. Demand: of 1,565 real prompts, none asked for a relationship graph, while finding and reading files ate 61.5% of tool-output tokens. Cost when one does: in a 5-task / 2-arm eval (cct, 2026-08-30, n=1 each) the graph arm answered all 5 in 4 turns and ~120k session tokens; the shell arm took 17 turns and ~473k and got 3 of 5 wrong. Reading a big file is a separate win — `cort context <symbol> --content full -f lean` returned one function from a 27,296-token file in 89 tokens, and an unchanged repeat read cost a 21-token receipt. Do not add these savings together.

Use this order for everyday work:

1. **Read one known function or method in a large indexed Rust file** — `cort context '<symbol>' --content full -f lean`. For methods, qualify the owner as `Type::method` (or `crate::path::Type::method`) to distinguish same-named methods. Check the header for `resolution=exact_symbol`; if an unqualified name returns multiple seeds, do not assume which one is intended.
2. **Read a file or line range you may need again** — `cort read <file> [--start N] [--end N] -f lean`. The first default read returns and persists the body. An unchanged repeat of the same range defaults to a one-line `source=store content=receipt` with no body; add `--content full` when you need the body again. Search only prior readings with `cort recall <query> -f lean`; add `--content full` for the complete stored fragment. Both commands validate the source, and require one prior `cort index`.
3. **Find a string, locate an unknown definition, or inspect a fresh edit** — `rg`. It sees working-tree changes immediately and is the right default for literal search. For the same literal string many times over a large repo, use `xg "PATTERN" --max-count 20` only when `command -v xg` succeeds.
4. **Trace callers or blast radius** — for an explicit relationship question **in TypeScript, TSX, JavaScript or Python**, `cort impact --symbol <name[,name2]> --depth <n> -f lean`, once. Batch seeds with commas; `--depth 1` for direct callers, the default 3 when genuinely transitive. If the question is relational, do not grep-walk the hops — that is the expensive, lossy version of this call (it missed symbols in 3 of 5 measured tasks). To check a surprising result, `cort context <dependent> --content full -f lean` reads one function, cheaper than re-reading files. Never route ordinary lookup here just because a graph exists. For **Rust**, `impact` indexes two call shapes only — bare calls (`foo()`) and fully-qualified associated calls (`Type::method()`); receiver calls (`x.method()`) and module-path calls (`crate::m::f()`) produce no edge, so `dependents=0` means "no indexed edge", not "nothing depends on this" — for the exact caller list use `cargo check`, for one hop `rg`.

One shape in one language → `ast-grep run -p '<pattern>' --lang <lang>`; add the enclosing symbols and neighbours → `cort struct -p '<pattern>' --lang <lang> -f lean`. Always pass `-f lean` (about a fifth of JSON's tokens); drop it only when you need to parse the output yourself.

Before trusting an indexed answer, check `stale=` (lean) or `index_is_stale` (JSON); if true, run `cort index --incremental` or fall back to `rg`. It covers two things: a file whose indexed content no longer matches disk, and a relationship graph not yet recomputed after its chunks changed (`graph_pending`, set by an interrupted or older-schema index; the next index rebuilds and clears it). New untracked files are invisible until indexed. `cort read`/`recall` ignore that field and validate the source instead.

Relationship resolution is name-based: a common unqualified name (a logging or fetch helper) can become a hub and pull in same-named symbols from unrelated files. Prefer owner-qualified Rust methods, spot-check depth-1 results, and treat deeper hops as candidates to confirm rather than verdicts. `AMBIGUOUS` rows are unresolved names, not edges.

`cort` finds its `ast-grep` parser without relying on the caller's PATH, so it works from a normalised agent shell. If you see `{"error":"ast_grep_missing"}` the error names the probed directories — run `./install.sh` or set `CORT_AST_GREP_BIN`. The binary is `ast-grep`, never `sg` (on Linux `/usr/bin/sg` is setgroups(1)).
