---
name: ast-grep
description: Route code lookup and caller-set work to rg, ast-grep, or cort. Use BEFORE renaming, deleting dead code, migrating, extracting, replacing or moving a symbol, and before any claim that nothing else uses it ("no callers", "not referenced anywhere", "safe to remove"), including when reviewing someone else's refactor — 改名前、刪掉前、移除前、遷移前、抽出去前、換掉前、確定沒人用嗎、還有哪裡在用、這樣改會不會漏、審這個重構. For literal strings, unknown definitions and fresh edits use rg; for one shape in one language use ast-grep.
---

Route by the narrowest output that answers the question. Two measurements set the order. Demand: in 1,214 genuine user instructions from local agent transcripts (`cort-evals demand`, 2026-08-31) exactly **one** asked a relationship question (0.08%), while 4-7 were tasks that cannot be done correctly without a call-site set — every one of them a delete, a refactor, or a review of one. The same corpus is 42% pasted agent reports being checked. Cost when the walk is needed: over 5 graph-required tasks x 2 arms x 2 rounds (cct, `evals/runs/2026-08-30-graph{,-sample2}/`) the `cort` arm answered 10/10 correctly in 4.2 turns and 992 tool-return tokens; the shell arm got 6/10 wrong in 16.8 turns and 7,642 tokens. Reading a big file is a separate win — `cort context <symbol> --content full -f lean` returned one function from a 27,296-token file in 89 tokens, and an unchanged repeat read cost a 21-token receipt. Do not add these savings together.

Use this order for everyday work:

1. **About to rename / delete / migrate / extract / replace / move a symbol, or about to write "nothing else uses this"** — `cort impact --symbol <name[,name2]> --depth <n> --coverage -f lean`, once, before the edit. This is the trigger that the data supports: nobody asks "who calls X", but the answer is required by the verbs above, and an agent that grep-walks them instead got multi-hop answers wrong in 6 of 10 measured cells. Batch seeds with commas; `--depth 1` for direct callers, the default 3 when genuinely transitive.
   **`--coverage` is not optional for a delete or a rename.** Plain `impact` answers "who calls this" and cannot see a caller it never extracted: measured on this repo, `dependents=0` with `stale=false` for a method with two live call sites, because `x.method()` is not an indexed Rust call shape. An empty `dependents` array is not clearance — an agent reading one as "safe to remove" is the exact failure this flag exists to stop. `--coverage` warns you when unmapped mentions, dropped resolutions or blind files *suggest* the enumeration missed a caller; it is a heuristic screen, not a proof of completeness: it never sees a caller in a file the indexer does not read at all (`.sh`, `.txt`, config), a re-export chain is flagged at the barrel line rather than at the eventual caller, and a common word (`get`, `add`, `new`) yields candidates you must triage. If `incomplete=true`, resolve the listed rows or fall back to `rg` before claiming absence.
2. **Read one known function or method in a large indexed Rust file** — `cort context '<symbol>' --content full -f lean`. For methods, qualify the owner as `Type::method` (or `crate::path::Type::method`) to distinguish same-named methods. Check the header for `resolution=exact_symbol`; if an unqualified name returns multiple seeds, do not assume which one is intended.
3. **Read a file or line range you may need again** — `cort read <file> [--start N] [--end N] -f lean`. The first default read returns and persists the body. An unchanged repeat of the same range defaults to a one-line `source=store content=receipt` with no body; add `--content full` when you need the body again. Search only prior readings with `cort recall <query> -f lean`; add `--content full` for the complete stored fragment. Both commands validate the source, and require one prior `cort index`.
4. **Find a string, locate an unknown definition, or inspect a fresh edit** — `rg`. It sees working-tree changes immediately and is the right default for literal search. For the same literal string many times over a large repo, use `xg "PATTERN" --max-count 20` only when `command -v xg` succeeds.
5. **An explicit relationship question, mid-investigation** — `cort impact` as in 1, in **TypeScript, TSX, JavaScript or Python**. If the question is relational, do not grep-walk the hops — that is the expensive, lossy version of this call. To check a surprising result, `cort context <dependent> --content full -f lean` reads one function, cheaper than re-reading files. Never route ordinary lookup here just because a graph exists. For **Rust**, `impact` indexes two call shapes only — bare calls (`foo()`) and fully-qualified associated calls (`Type::method()`); receiver calls (`x.method()`) and module-path calls (`crate::m::f()`) produce no edge, so `dependents=0` means "no indexed edge", not "nothing depends on this" — for the exact caller list use `cargo check`, for one hop `rg`.

One shape in one language → `ast-grep run -p '<pattern>' --lang <lang>`; add the enclosing symbols and neighbours → `cort struct -p '<pattern>' --lang <lang> -f lean`. Always pass `-f lean` (about a fifth of JSON's tokens); drop it only when you need to parse the output yourself.

Before trusting an indexed answer, check `stale=` (lean) or `index_is_stale` (JSON); if true, run `cort index --incremental` or fall back to `rg`. It covers two things: a file whose indexed content no longer matches disk, and a relationship graph not yet recomputed after its chunks changed (`graph_pending`, set by an interrupted or older-schema index; the next index rebuilds and clears it). New untracked files are invisible until indexed. `cort read`/`recall` ignore that field and validate the source instead.

Relationship resolution is name-based: a common unqualified name (a logging or fetch helper) can become a hub and pull in same-named symbols from unrelated files. `lean` prints each dependent's own **definition** line, not the line where it calls the parent, so confirming one specific edge still costs a read — spot-check depth-1 results and treat deeper hops as candidates to confirm rather than verdicts. Prefer owner-qualified Rust methods. `AMBIGUOUS` rows are unresolved names, not edges.

`cort` finds its `ast-grep` parser without relying on the caller's PATH, so it works from a normalised agent shell. If you see `{"error":"ast_grep_missing"}` the error names the probed directories — run `./install.sh` or set `CORT_AST_GREP_BIN`. The binary is `ast-grep`, never `sg` (on Linux `/usr/bin/sg` is setgroups(1)).
