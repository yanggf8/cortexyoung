name: cort
description: Use when starting work in a repo, after context compaction or a resumed session, before asserting a project fact (a decision, a machine's state, what was retired, "we decided"), when the user corrects an assumption, when a decision is made or changed, or when deployment changes what a machine runs — 之前決定了什麼、記一下、記起來、上次怎麼說、被糾正. Also use before renaming, deleting, migrating, extracting, replacing or moving a symbol, or claiming nothing uses it — 改名前、刪掉前、移除前、遷移前、抽出去前、換掉前、確定沒人用嗎、還有哪裡在用、這樣改會不會漏、審這個重構.
---

Recall project decisions and corrections with `cort memory recall "<topic>"` at the start of work, after compaction or resumption, and before asserting a project fact. A hit whose `evidence_status` is not `source_unchanged` is a lead to re-check, not a fact. If recall reports that cort memory is not configured, or that it cannot identify this project, say so and continue without it; do not retry.

Record a decision made or changed, a user correction, or a deployment change with `cort memory record --key <key> --claim <claim> --source <repo file> --line <n>`. Cite a line in a doc, plan or code file that states the claim; the whole file must be committed and clean at HEAD, so if no line states it yet, write and commit that line first. Replace the sole active claim with `--replace`, or pass `--supersedes <id>` (a unique lowercase hex prefix of at least 8 characters works); repeat `--supersedes` for every active id to resolve a conflict. Harness-private memory must never be the only copy of a project fact.

Before renaming, deleting, migrating, extracting, replacing or moving a symbol, or claiming nothing uses it, run `cort impact --symbol <name> --depth 1 --coverage -f lean`. Read the dependent call-site lines and the coverage rows, not just the boolean. An empty `dependents` array is not clearance.

`enumeration_may_be_incomplete=true` has exactly two causes, named in `why`: a named gap row (`mentions_without_edge`, `extracted_but_unresolved`), or a file this screen never read (`blind_files` for unindexed, `scan_skipped` for >2 MB / unreadable). `false` entitles you to one conclusion only: every file the screen read produced no gap signal for that seed. It is not "nothing else uses this" — silent either way are a caller in a file the indexer never reads (`.sh`, `.txt`, config, anything under `dist/`, `build/`, `target/`, `node_modules/`), a re-export chain (flagged at its barrel line, not at the eventual caller), a mention within 2 lines of an extracted call (counted covered), and a call that exists only after macro expansion. `unparsed_files` in `why` is advisory: a chunk-less file was read as text, so it never flips the boolean. If `true`, resolve the listed rows or use `rg` before claiming absence; on common words the rows are candidates to triage, not verdicts. The printed list is capped at 20: `no_edge=` counts every mention gap, separate `drop` rows are never truncated, and `miss\ttruncated\tshown=N\tof=M` means M-N lower-ranked rows were cut; `-f json` has the rest.

Use `rg` for literal strings and fresh edits; use `ast-grep run` for one structural shape in one language.
